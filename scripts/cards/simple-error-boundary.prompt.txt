```ts
interface SimpleErrorBoundaryProps {
  fallback: React.ReactNode | ((error: Error) => React.ReactNode);
  onError?: (error: Error, errorInfo?: React.ErrorInfo) => void;
  children: React.ReactNode;
}

interface SimpleErrorBoundaryState {
  error: Error | null;
}
```

Write `SimpleErrorBoundary` as a class component:

### class SimpleErrorBoundary extends React.Component<SimpleErrorBoundaryProps, SimpleErrorBoundaryState>

**Why a Class Component?**
Even in modern React (React 18 & 19), React does not provide a Hook equivalent for error boundaries. Catching rendering exceptions requires the class lifecycle methods `static getDerivedStateFromError` and `componentDidCatch`. Writing an error boundary class is the standard, canonical pattern across modern React codebases and libraries (including `react-error-boundary`).

- **Initial State**:
  - Initializes state with `{ error: null }`.
- **Catching Render Errors**:
  - Catches descendant render errors via `static getDerivedStateFromError(error)` and updates state with `{ error }`.
  - Invokes `onError?.(error, errorInfo)` in `componentDidCatch(error, errorInfo)` when the `onError` prop is provided.
- **Rendering**:
  - If an error has occurred (`error !== null`), renders `fallback` (or `fallback(error)` if `fallback` is a function).
  - Otherwise, renders `children` normally.
- **Fault Isolation**:
  - A failure inside one boundary must not affect sibling boundaries or parent components outside it.
