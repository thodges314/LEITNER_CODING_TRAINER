Implement an in-memory client-side router with path parameters and query string parsing:

### `matchRoute(pattern: string, pathname: string): Record<string, string> | null`
- Matches a pathname against a pattern and extracts route parameters (supports `:param` and `*` wildcard).

### `createRouter(routes: Array<{ pattern: string; name: string }>, initialPath?: string): Router`
- `routes` is an array of route definitions: `[{ pattern: '/users/:id', name: 'user' }, ...]`.
- Initialized with `initialPath` (defaults to `'/'`).

#### Route Resolution
- Matches paths against route patterns:
  - Segments starting with `':name'` capture dynamic parameters into `params: { name: value }`.
  - Empty segments (leading, trailing, and duplicate slashes) are ignored.
  - Query parameters (e.g. `'?q=hi&page=2'`) are parsed into `query: { q: 'hi', page: '2' }`.
  - If no route matches, resolves to `{ path, name: null, params: {}, query }`.

#### Router API
- **`current()`**: Returns the currently active resolved route object `{ path, name, params, query }`.
- **`navigate(path)`**: Pushes `path` onto history, drops forward history, updates the current route, and notifies listeners.
- **`back()`**: Moves one step back in history (if possible) and notifies listeners.
- **`forward()`**: Moves one step forward in history (if possible) and notifies listeners.
- **`subscribe(listener)`**: Subscribes `listener(route)` to navigation events and returns an unsubscribe function.
