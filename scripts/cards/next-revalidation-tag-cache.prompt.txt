Implement an idiomatic Next.js Server Action that performs a data mutation and purges the Next.js Data Cache:

## Description

### Application Context
In Next.js App Router applications (`app/actions/products.ts`), data mutations are commonly performed in Server Actions marked with the `'use server'` directive. Next.js manages full route caching and data caching automatically. When a write operation completes successfully, developers call `revalidateTag` and `revalidatePath` from `next/cache` to purge stale cached data on-demand across all routes consuming that tag or path.

You are writing a Server Action `updateProduct` that sends a `PATCH` request to an external product API, checks the response status, purges relevant cache tags on success, and returns a structured action result.

```ts
interface UpdateProductInput {
  id: string;
  price: number;
}

interface ActionResult {
  success: boolean;
  error?: string;
}
```

### `updateProduct({ id, price }: UpdateProductInput): Promise<ActionResult>`

- **Server Action Context**:
  - Operates as a Server Action (you may include the `'use server'` directive).
- **Data Mutation**:
  - Dispatches a `PATCH` request to `https://api.example.com/products/${id}` via `fetch()` with:
    - `method: 'PATCH'`
    - `headers: { 'Content-Type': 'application/json' }`
    - `body: JSON.stringify({ price })`
- **Error Handling**:
  - If the response is not ok (`!res.ok`), does NOT purge any caches, and returns `{ success: false, error: 'Update failed' }`.
- **On-Demand Cache Purging**:
  - When `res.ok` is `true`:
    - Purges the collection tag by calling `revalidateTag('products')` from `next/cache` (or ambient `revalidateTag`).
    - Purges the product detail path by calling `revalidatePath('/products/' + id)` from `next/cache` (or ambient `revalidatePath`).
    - Returns `{ success: true }`.
