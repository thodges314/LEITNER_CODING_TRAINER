Write a PostgreSQL query to sessionize user event streams into distinct browsing sessions. A new session begins whenever an event occurs more than 30 minutes after the user's immediately preceding event, or when an event is the user's first recorded event.

### Schema: `user_events`
- `event_id` (INT, PRIMARY KEY): Unique event identifier.
- `user_id` (INT): User identifier.
- `event_time` (TIMESTAMP): Timestamp of the event.

### Query Contract
- Output columns: `event_id`, `user_id`, `session_id`.
- `session_id`: String formatted as `<user_id>-<session_seq>` (e.g. `'1-1'`, `'1-2'`, `'2-1'`), where `session_seq` starts at 1 for each user and increments sequentially by 1 on every new session for that user.
- Sort results by `event_id` ascending (`ORDER BY event_id ASC`).
- If `user_events` is empty, return an empty result set (0 rows).

### Example
Given `user_events` records:
- `{ event_id: 1, user_id: 1, event_time: "2024-01-01 10:00:00" }`
- `{ event_id: 2, user_id: 1, event_time: "2024-01-01 10:15:00" }`
- `{ event_id: 3, user_id: 1, event_time: "2024-01-01 10:50:00" }`
- `{ event_id: 4, user_id: 2, event_time: "2024-01-01 12:00:00" }`

The query returns:
- `[{ "event_id": 1, "user_id": 1, "session_id": "1-1" }, { "event_id": 2, "user_id": 1, "session_id": "1-1" }, { "event_id": 3, "user_id": 1, "session_id": "1-2" }, { "event_id": 4, "user_id": 2, "session_id": "2-1" }]`

Explanation:
- Event 2 is 15 minutes after Event 1 ($\le$ 30 min), so it stays in session `'1-1'`.
- Event 3 is 35 minutes after Event 2 (> 30 min), so it increments to session `'1-2'`.
- Event 4 is user 2's first event, so it begins session `'2-1'`.
