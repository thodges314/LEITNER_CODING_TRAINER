Implement Next.js App Router Layout and Template composition components:

## Description

### Application Context
In the Next.js App Router (`app/dashboard/layout.tsx` vs `app/dashboard/template.tsx`), layouts and templates compose component hierarchies. Layouts preserve state and avoid unnecessary re-renders across client-side navigation between sibling routes (e.g. `/dashboard/analytics` to `/dashboard/settings`), whereas templates create a fresh instance on every navigation (re-triggering entrance animations or resetting page state). In Next.js, this is achieved by nesting the template with a route-dependent `key` inside the layout: `<Layout><Template key={pathname}>{children}</Template></Layout>`.

```ts
interface LayoutProps {
  children: React.ReactNode;
}

interface TemplateProps {
  children: React.ReactNode;
  key?: string;
}

interface DashboardRootProps {
  pathname: string;
  children: React.ReactNode;
}
```

### Components

- **`DashboardLayout({ children }: LayoutProps): React.ReactElement`**:
  - Renders a container `<div data-testid="dashboard-layout">` holding:
    - `<header data-testid="dashboard-header">Dashboard Shell</header>`
    - `<main>{children}</main>`
- **`DashboardTemplate({ children }: TemplateProps): React.ReactElement`**:
  - Renders `<div data-testid="dashboard-template" className="template-enter">{children}</div>`.
- **`DashboardRoot({ pathname, children }: DashboardRootProps): React.ReactElement`**:
  - Composes the components: renders `DashboardLayout` containing `DashboardTemplate` with `key={pathname}` wrapping `{children}`.
