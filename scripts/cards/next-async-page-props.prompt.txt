Implement a Next.js 15 async Server Component page that consumes asynchronous route parameters and search query params:

## Description

### Application Context
In Next.js 15 (`app/shop/[category]/page.tsx`), page and layout components receive dynamic route `params` and `searchParams` as asynchronous `Promise` objects. You are building an authentic async Server Component page that awaits both promises, normalizes query values, and renders structured semantic UI.

```ts
type SearchParamsValue = string | string[] | undefined;

interface PageProps {
  params: Promise<{ category: string }>;
  searchParams: Promise<Record<string, SearchParamsValue>>;
}
```

### `CategoryPage({ params, searchParams }: PageProps): Promise<React.ReactElement>`

- **Awaits Async Arguments**:
  - Awaits `params` to resolve the dynamic route parameters `{ category: string }`.
  - Awaits `searchParams` to resolve query parameter records.
- **Normalization**:
  - **Category**: Reads `category` from resolved `params`. If missing or empty, defaults to `'all'`.
  - **Sort**: Reads `sort` from `searchParams`. If passed as an array, takes the first non-empty string. If omitted or empty, defaults to `'featured'`.
  - **Page**: Reads `page` from `searchParams`. If passed as an array, takes the first string. Parses as integer; if positive (`>= 1`), uses that number, otherwise defaults to `1`.
- **Render Output**:
  - Returns a `<main data-testid="category-page">` container rendering:
    - `<h1 data-testid="category-title">{category}</h1>`
    - `<span data-testid="sort-value">{sort}</span>`
    - `<span data-testid="page-value">{page}</span>`
