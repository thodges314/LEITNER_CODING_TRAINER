Implement requestAnimationFrame-based throttling for high-frequency events:

### rafThrottle<TArgs extends unknown[]>(fn: (...args: TArgs) => void, raf?: (cb: (time: number) => void) => number, caf?: (handle: number) => void): ThrottledFunction<TArgs>
- Returns a throttled function that invokes `fn` at most once per animation frame.
- Defaults to window `requestAnimationFrame` and `cancelAnimationFrame` (can be dependency-injected in tests).

#### Throttling Mechanics
- Remembers the latest arguments passed across invocations.
- The first invocation schedules a frame via `raf(...)`. Subsequent calls before that frame fires simply replace the arguments.
- When the frame executes:
  - Invokes `fn` once with the latest arguments.
  - Clears the active frame ID so subsequent calls (including calls inside `fn`) can schedule a new frame.

#### Cancellation
- The returned throttled function exposes a `.cancel()` method:
  - If a frame is pending, cancels it via `caf(frameId)` and clears the pending state.
  - Does nothing (and does not call `caf`) if no frame is currently pending.
